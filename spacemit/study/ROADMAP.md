# 学习路线：按技术主线组织

## 两条原则

1. **按技术主线分讲，不按文档库分讲。** 同一个技术点往往在 3–4 份库里各讲一个侧面，一讲要把它们拼起来。
2. **先懂产品，再懂芯片，最后懂软件怎么跑起来。** 产品是你能摸到的东西，芯片解释它为什么这样，软件解释它怎么被用起来。

## 每个模块的构成

统一为：**3 篇短课 + 1 份测验（三段式）**。

- 短课：每篇 10–15 分钟，只讲一件事。
- 测验：三段式，见下。分数不作门槛。

### 测验的三段结构

原来的"开放式最终回顾"要求写一段话，但多数人不愿意写字。改成**全选做题，零书写要求**：

| 段 | 形式 | 检查什么 |
|---|---|---|
| **一、基础题** | 单选，正误明确 | 有没有基础概念混淆 |
| **二、认陷阱** | 单选或多选，选项是常见的**错误说法** | 会不会被似是而非的说法骗到 |
| **三、自评** | 按知识点逐条点选：懂了 / 有疑问 / 没懂 | 只作记录，帮下次回看哪一节 |

关键设计规则：

1. **自评按知识点拆开**，不要笼统问"整体理解了吗"。一个概念一行，点选即可。
2. **自评不做判断依据**。它只是线索，告诉你下次重点讲什么。
3. **认陷阱题的选项要来自真实的常见误解**，不能随手编。答错能直接暴露是哪一步没想通。
4. 写字完全可选。想写的人可以写，不写也不影响完成。

**认陷阱题示例**（M3 内存）：

> 下面哪句话是错的？
> A. 算力再高，数据送不到计算单元也发挥不出来
> B. LPDDR5 比 LPDDR4x 快，所以配 LPDDR5 的板子 AI 一定跑得更快
> C. 模型能不能跑，要看算力、带宽、容量里最紧的那个
>
> 答案 B。"型号更快"只是接口规格，实际速度还取决于配置、访问模式和模型本身。

**多选题示例**（M3 内存）：

> 要判断这个模型能不能在这块板子上跑起来，你会查哪些？（可多选）
> 内存容量 / 内存带宽 / 模型参数量 / 量化方式 / 芯片的 TOPS 数值 / 引擎版本

## 各模块要点

### M1 我们卖什么：产品线全景
- 三个系列：K1（边缘 AI）、K3（高性能端侧 AI）、V100（数据中心通用计算）
- 每个系列下的整机形态：模组、开发板、设备、服务器
- **跨库点**：产品资料说"兼容 Orin Nano""768 核"，芯片资料能解释这些数字怎么来的

### M2 一颗芯片里有什么
- 8 个 X100 通用核 + 8 个 A100 AI 核 + RT24 实时核
- 为什么是两簇 × 四核，簇的意义
- **跨库点**：芯片手册讲架构，产品资料讲整机规格，两者数字要能对上

### M3 内存与存储
- LPDDR4x/5、64 位位宽、为什么带宽是 AI 的瓶颈
- UFS / eMMC / SD / QSPI 四种存储接口各自给谁用
- **跨库点**：芯片讲控制器规格，产品讲实际配了多大容量，Buildroot 讲 DDR 驱动

### M4 启动：从上电到系统跑起来
- Boot ROM → 一级引导 → U-Boot → 内核 → 根文件系统
- 启动模式选择、安全启动的介入点
- **跨库点**：这是最能体现"一讲串六个库"的主题——芯片讲 Boot Mode，Buildroot 讲 U-Boot 和设备树，Bianbu 讲镜像怎么做，产品讲刷机步骤，工具讲烧录工具

### M5 两套系统：Buildroot 与 Bianbu
- Buildroot：可裁剪、面向嵌入式
- Bianbu：基于 Ubuntu、面向通用计算，有桌面版和命令行版
- 为什么同一颗芯片要两套系统
- **跨库点**：两个库的定位差异 + 产品资料里的 SDK 选择

### M6 设备树与外设驱动
- 设备树在描述什么
- UART / I2C / SPI / GPIO / PWM 这类低速外设的共性
- **跨库点**：芯片讲外设控制器，Buildroot 讲驱动和绑定

### M7 显示与图形
- DPU0 / DPU1 的接口不对称，MIPI-DSI 与 DP/eDP 的区别
- GPU：TBDR、Vulkan/OpenCL/OpenGL ES
- **跨库点**：芯片讲显示控制器，Buildroot 讲驱动框架和 panel porting，产品讲载板引出的是哪个口

### M8 摄像头与多媒体
- MIPI-CSI 的通道分配与共享 PHY
- ISP、VPU、JPU 在流水线里的位置
- **跨库点**：芯片讲接口和编解码能力，Buildroot 讲 MPP 框架和摄像头驱动

### M9 AI 的硬件基础
- A100 核：VLEN 1024、Scratchpad/TCM、算子级并行
- IME 指令集在做什么
- **跨库点**：芯片手册的规格 + AI 库的架构文档

### M10 AI 软件栈
- 推理引擎（ONNX Runtime / llama.cpp / vLLM）各管什么
- 量化：为什么能省资源，代价是什么
- **跨库点**：AI 库为主，Buildroot 讲安装与依赖

### M11 安全与可信
- 安全启动、TEE、密钥生命周期
- PMP/IOPMP、OP-TEE
- **跨库点**：芯片讲硬件安全引擎，Buildroot 讲安全子系统，产品讲支持矩阵

### M12 网络与高速互联
- PCIe 通道分配与 USB 的 PHY 共享
- 以太网、TSN、Wi-Fi/蓝牙
- **跨库点**：芯片讲控制器，Buildroot 讲驱动，产品讲 RV2768 的集群网络

### M13 实时核与异构计算
- RT24 实时核做什么
- 异构系统里谁调度谁
- **跨库点**：Buildroot 的 `esos/` + 芯片手册的实时处理子系统

### M14 开发工具与调试
- Studio、交叉编译、烧录、JTAG、Trace
- 内核调试手段
- **跨库点**：工具库为主，Buildroot 的 `kernel_debug/` 补充

### M15 行业方案
- AI Computer、AI Robot 这些方案在做什么
- 技术能力怎么描述成客户价值
- **跨库点**：AI 库的 solutions + 产品资料
