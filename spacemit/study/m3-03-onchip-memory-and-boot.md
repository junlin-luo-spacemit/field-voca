# 片上存储与启动流程

> **本讲目标**：理解 K3 片上存储（Boot ROM、SRAM）的用途，知道芯片上电后如何从 Boot ROM 一步步加载操作系统，以及各种存储接口在启动过程中的角色。
>
> **📌 说明**：本模块以 **K3** 为例讲解启动流程，但片上存储的层次结构和多级引导的设计思路适用于所有 SoC 芯片。

## 一、K3 的片上存储

K3 集成了两种片上存储：

| 类型 | 容量 | 用途 |
|---|---|---|
| Boot ROM | 128 KB | 一级引导代码，只读，出厂固化 |
| SRAM | 512 KB | 主 CPU 和 RCPU 共享，掉电数据丢失 |

**Boot ROM（启动只读存储器）**：
- 芯片出厂时固化，不可修改
- 存放最初的引导代码
- 支持从多种外部介质启动：eMMC、UFS、SD、QSPI NOR Flash、USB、UART
- 支持基于 eFuse 的安全启动

**SRAM（静态随机存取存储器）**：
- 芯片内部的高速静态内存，由主 CPU 和实时核（RCPU）共享
- 上电后立即可用，不需要初始化
- 容量小，主要用于启动早期阶段（LPDDR5 未就绪前）

## 二、启动流程概览

芯片上电后无法直接运行完整的操作系统，需要多个阶段逐步加载：

```
上电复位
  ↓
Boot ROM（片上，128 KB）读取引导代码
  ↓
初始化 LPDDR5，从外部存储加载引导程序
  ↓
从 eMMC/UFS 加载操作系统
  ↓
系统运行
```

**为什么需要多阶段？**
- Boot ROM 只有 128 KB，放不下完整的操作系统
- LPDDR5 需要初始化后才能使用，初始化代码本身需要临时运行在 SRAM 中

## 三、启动模式选择

K3 支持多种启动介质，通过硬件引脚在上电时选择：

| 启动模式 | 典型用途 |
|---|---|
| eMMC 启动 | 量产设备的标准启动方式 |
| UFS 启动 | 高性能设备 |
| SD 卡启动 | 开发调试，方便换系统镜像 |
| QSPI 启动 | 存放早期引导代码，快速启动 |
| USB / UART 下载 | 烧录固件、恢复设备 |

**开发板通常支持 SD 卡启动**，原因是 SD 卡可以热插拔，更换系统镜像只需换一张卡。量产设备通常固定用 eMMC 或 UFS 启动。

## 四、安全启动

**安全启动（Secure Boot）** 基于 eFuse（一次性可编程熔断丝）：

- **eFuse** 中存储了公钥哈希值，出厂后无法修改
- 每个引导阶段都验证下一阶段的签名，确保代码没有被篡改
- 如果验证失败，启动停止，防止恶意代码运行

**作用**：保证设备只运行经过授权的软件，防止固件被替换或篡改。这是量产设备的标准安全机制。
