# 启动流程：从上电到系统运行

> **本讲目标**：知道 K3 芯片从上电到 Linux 运行要经过哪些阶段，每个阶段叫什么名字、做什么事。
>
> **📌 说明**：本模块以 **K3** 为例，但多级引导的思路适用于所有 SoC 芯片。

## 一、为什么不能直接启动

芯片上电后无法直接运行 Linux，原因有两个：

1. **容量太小**：Boot ROM 只有 128 KB，放不下完整的操作系统
2. **内存还没准备好**：LPDDR5 在上电后需要初始化，才能被使用

因此 K3 的启动分成多个阶段，每个阶段负责初始化一部分硬件、加载下一个阶段，直到系统完全运行。

## 二、K3 的启动链路

```
上电
  ↓
① Boot ROM（芯片出厂固化，只读）
  - 决定从哪个存储介质启动
  - 加载引导程序到内存中运行
  ↓
② 引导程序（FSBL）
  - 完成内存（LPDDR5）的初始化
  - 加载操作系统所需的软件
  ↓
③ U-Boot（通用启动程序）
  - 把 Linux 内核加载到内存
  - 把设备描述文件（设备树）加载到内存
  ↓
④ Linux 内核
  - 读取设备描述文件，识别板子上的硬件
  - 挂载文件系统，启动系统服务
  ↓
⑤ 系统正常运行
```

> **OpenSBI** 是一个运行在 Boot ROM 和 U-Boot 之间的中间层，专为 RISC-V 架构设计，负责在最底层管理硬件资源并对上层软件提供标准接口。技术写作中通常不需要单独介绍它，但你会在文档中看到这个名词。

## 三、设备树是什么

**设备树**（Device Tree）是一个描述文件，记录了板子上有哪些硬件、各自连接在哪里。

**为什么需要它？**  
同一颗 K3 芯片可以装在不同的板子上，每块板子接了不同的屏幕、摄像头、存储器。内核启动时读取设备树，就知道这块板子的具体配置是什么，不需要为每块板子单独写代码。

**类比**：设备树像一份房屋平面图——同样的建筑结构（内核），配上不同的平面图（设备树），就能适配不同的房屋布局（板子）。

## 四、固件存放在哪里

K3 的启动软件按分区存放在 eMMC 或其他存储介质上：

| 分区 | 存放内容 |
|---|---|
| 引导分区 | 引导程序（FSBL）、U-Boot |
| 内核分区（bootfs） | Linux 内核 + 设备树 |
| 系统分区（rootfs） | 操作系统文件 |
| 用户数据分区 | 应用数据（可选） |
