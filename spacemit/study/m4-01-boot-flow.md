# 启动流程：从上电到系统运行

> **本讲目标**：知道 K3 芯片从上电到 Linux 运行要经过哪些阶段，每个阶段叫什么名字、做什么事。
>
> **📌 说明**：本模块以 **K3** 为例，但多级引导的思路适用于所有 SoC 芯片。

## 一、为什么不能直接启动

芯片上电后无法直接运行 Linux，原因有两个：

1. **容量太小**：[Boot ROM](GLOSSARY.md#boot-rom) 只有 128 KB，放不下完整的操作系统
2. **内存还没准备好**：LPDDR5 在上电后需要初始化，才能被使用

因此 K3 的启动分成多个阶段，每个阶段负责初始化一部分硬件、加载下一个阶段，直到系统完全运行。

## 二、K3 的启动链路

```
上电
  ↓
① Boot ROM（芯片出厂固化，只读）
  - 决定从哪个存储介质启动
  - 加载引导程序到内存中运行
  ↓
② 引导程序（FSBL）
  - 完成内存（LPDDR5）的初始化
  - 加载操作系统所需的软件
  ↓
③ OpenSBI（RISC-V 固件层）
  - 在最底层管理硬件资源
  - 对上层软件提供标准接口
  ↓
④ U-Boot（通用启动程序）
  - 把 Linux 内核加载到内存
  - 把设备描述文件（设备树）加载到内存
  ↓
⑤ Linux 内核
  - 读取设备描述文件，识别板子上的硬件
  - 挂载文件系统，启动系统服务
  ↓
⑥ 系统正常运行
```

**举例**：你按下开发板电源键后，Boot ROM 在 0.1 秒内检测启动介质并加载 FSBL，FSBL 花 0.5 秒初始化内存，OpenSBI 和 U-Boot 再用 1-2 秒加载内核，最后 Linux 启动到登录界面大约需要 5-10 秒。

**启动流程时间线**（典型耗时）：

```
上电 (t=0)
  ↓
┌──────────────────┐
│   Boot ROM       │  0.1 秒 ← 检测启动介质，加载 FSBL
│   (芯片内部)      │           FSBL 存在 eMMC/SD/UFS
└────────┬─────────┘
         ↓
┌──────────────────┐
│     FSBL         │  0.5 秒 ← 初始化 LPDDR5 内存
│   (运行在 SRAM)   │           为后续软件准备运行环境
└────────┬─────────┘
         ↓
┌──────────────────┐
│   OpenSBI        │  1-2 秒 ← 加载 U-Boot、内核、设备树
│   + U-Boot       │           U-Boot 把内核拷贝到内存
└────────┬─────────┘
         ↓
┌──────────────────┐
│  Linux 内核       │  5-10 秒← 挂载文件系统、启动服务
│                  │           到达登录界面
└──────────────────┘
```

**关键观察**：
- 前 0.6 秒完成"从零到内存可用"
- 1-2 秒内核加载到内存
- 大部分时间花在 Linux 自身启动（服务初始化、文件系统检查）

## 三、OpenSBI 是什么

**[OpenSBI](GLOSSARY.md#opensbi)**（Open Supervisor Binary Interface）是 RISC-V 架构特有的固件层，运行在引导程序和 U-Boot 之间。

**它解决什么问题？**  
不同的 RISC-V 芯片底层硬件实现各不相同（定时器、中断控制器、电源管理）。如果 Linux 内核直接操作这些硬件，就需要为每颗芯片写不同的代码。

OpenSBI 提供了一套标准接口（SBI），Linux 内核通过 SBI 请求底层服务，不需要知道具体芯片的实现细节。

**类比**：OpenSBI 像是操作系统和硬件之间的"翻译官"——内核说"我要设置定时器"，OpenSBI 把这个标准请求翻译成 K3 具体寄存器的操作。

**对技术写作人员的意义**：你会在启动流程文档和安全启动文档中看到 OpenSBI 这个名词，知道它是"内核和硬件之间的中间层"就足够了。

## 四、设备树是什么

**[设备树](GLOSSARY.md#设备树)**（Device Tree）是一个描述文件，记录了板子上有哪些硬件、各自连接在哪里。

**为什么需要它？**  
同一颗 K3 芯片可以装在不同的板子上，每块板子接了不同的屏幕、摄像头、存储器。内核启动时读取设备树，就知道这块板子的具体配置是什么，不需要为每块板子单独写代码。

**类比**：设备树像一份房屋平面图——同样的建筑结构（内核），配上不同的平面图（设备树），就能适配不同的房屋布局（板子）。

## 五、固件存放在哪里

K3 的启动软件按分区存放在 eMMC 或其他存储介质上：

| 分区 | 存放内容 |
|---|---|
| 引导分区 | 引导程序（[FSBL](GLOSSARY.md#fsbl)）、[U-Boot](GLOSSARY.md#u-boot) |
| 内核分区（bootfs） | Linux 内核 + 设备树 |
| 系统分区（rootfs） | 操作系统文件 |
| 用户数据分区 | 应用数据（可选） |
