# 启动模式与固件刷写

> **本讲目标**：知道 K3 有哪几种启动方式，知道"刷固件"是什么意思，以及什么场景下会用到这些操作。
>
> **📌 说明**：本模块以 **K3** 为例，但下载模式、正常启动、固件刷写的概念适用于所有 SoC 产品。

## 一、两种启动类型

K3 支持两种大类启动：

| 类型 | 用途 | 适用场景 |
|---|---|---|
| **下载模式** | 通过 USB 或串口接收固件 | 烧录新固件、恢复设备、工厂生产 |
| **正常启动** | 从存储介质（eMMC/SD/UFS等）加载系统 | 日常使用 |

**下载模式**下，设备不从存储介质启动，而是通过数据线等待 PC 传送固件。

## 二、SD 卡优先

K3 有一个重要的设计规则：**始终先尝试从 SD 卡启动**。

- 插入 SD 卡且卡内有有效系统 → 从 SD 卡启动
- 没有 SD 卡 → 从其他介质（eMMC、UFS 等）启动

**这就是开发板通常用 SD 卡来切换系统的原因**：不需要修改任何设置，插卡就切换，拔卡就恢复。量产设备通常不插 SD 卡，直接从 eMMC 启动。

## 三、固件刷写是什么

**刷写**（也称"烧录"）是把 PC 上准备好的系统镜像文件传输并写入到设备存储介质的操作。

K3 使用 **Fastboot** 协议完成刷写。Fastboot 是 Android 生态广泛使用的设备刷机协议，速度快、兼容性好。

**进入刷写模式的三种方式**：

1. **按键组合**：同时按住 FEL 键和 RESET 键，设备进入等待刷机状态
2. **ADB 命令**（设备已有系统时）：在 PC 执行 `adb reboot bootloader`
3. **串口操作**（开发调试时）：启动时通过串口长按 `s` 键

## 四、卡量产与卡启动

这两个概念容易混淆：

| 概念 | 说明 |
|---|---|
| **卡启动** | 系统运行在 SD 卡上，拔卡系统就没了 |
| **卡量产** | 用 SD 卡当"搬运工"，把系统写入 eMMC，之后从 eMMC 运行 |

**卡量产的典型用途**：工厂批量生产，不需要逐台连电脑，插卡自动完成写入。
