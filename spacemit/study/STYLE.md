# 课程与测验规范

这份文件定义两件事：**课程怎么写、怎么排**，**测验怎么出题、怎么反馈**。

所有模块按此执行。规则写得具体，是为了能检查，不是因为要死守。

---

## 第一部分：课程写作

### 1. 必须有可核对的参考来源

每篇课末尾放一张表，列出这篇课用到的所有出处。

| 小节标题 | 库 | 文件路径 | 章节 |
|---|---|---|---|
| 两个不同的核 | docs-chip | `key_stone/k3/k3_docs/k3_ds.md` | 2.1.1、2.1.2 |
| 内存带宽 | docs-chip | `key_stone/k3/k3_docs/k3_ds.md` | 1.2、2.2.2 |
| CoM260 规格 | docs-product | `k3_series/k3_com260/root_overview.md` | 产品规格 |

规则：

- 表里**只写真实存在的路径和章节**。没读过的不写。
- 引用数字时，在表格里注明版本或日期。
- 找不到官方出处的说法，就不写进课里。

### 2. 短句，一段一件事

| 项 | 规则 |
|---|---|
| 单句长度 | 不超过 40 个汉字。超了就拆成两句。 |
| 段落 | 一段最多 4 句。 |
| 每小节 | 只讲一个概念。出现"另外还有"就该另起一节。 |
| 列表优先 | 能列成 3 条以上的并列信息，用表格或列表，不写成一段话。 |

**不合规**：

> X100 是一款高性能、四发射、乱序执行的多核多簇 RISC-V 处理器，符合 RVA23 指令集架构规范，专为服务器、自动驾驶系统及云端 AI 推理平台等高负载计算场景优化设计，同时具备完善的虚拟化能力、强大的安全韧性以及 RAS 特性。

**合规**：

> X100 是通用 CPU 核。
>
> - 四发射、乱序执行
> - 符合 RVA23 规范
> - 面向服务器、自动驾驶、云端推理

### 3. 术语必须带英文

正文用中文，但每个技术术语**首次出现时**写成：**中文（English，缩写全称）**

示例：

- 直接存储器访问（Direct Memory Access，DMA）
- 紧耦合存储器（Tightly Coupled Memory，TCM）
- 根复合体（Root Complex，RC）

规则：

- 同一篇课内，第二次出现可以只写中文或只写英文。
- 缩写第一次出现必须展开全称，不能只写 DMA。
- 芯片型号、寄存器名、文件路径保持原文，不翻译。

### 4. 数字必须带条件

任何性能、容量、速率数字，都要写清适用条件。

**不合规**：

> AI 算力 60 TOPS。

**合规**：

> AI 算力 60 TOPS（@INT4 sparse，即 INT4 精度、稀疏计算模式下）。

规则：

- 有括号限定的，括号内容不能省。
- 表格里的"见注 X"，注释内容要一起给。
- 峰值、典型值、平均值必须写明是哪一个。

### 5. 每篇课的结构

固定四段：

| 段 | 内容 |
|---|---|
| 开头一句 | 这篇课讲什么，一句话说完 |
| 正文 | 2–4 个小节，每节一个概念 |
| 快速自测 | 3 个问句，不给答案，只提示回看哪节 |
| 参考来源 | 见第 1 条 |

篇幅控制在 10–15 分钟能读完。

## 第二部分：测验出题

### 1. 三段结构

| 段 | 形式 | 题量 | 检查什么 |
|---|---|---|---|
| 一、基础题 | 单选 | 4 题 | 有没有基础概念混淆 |
| 二、认陷阱 | 单选或多选 | 4 题 | 会不会被似是而非的说法骗到 |
| 三、自评 | 按知识点点选 | 每个知识点 1 行 | 只作记录，不作判断 |

**全程不要求写字。**

### 2. 选项不能一眼看出答案

这是最容易做坏的地方。规则：

| 规则 | 说明 |
|---|---|
| 长度接近 | 四个选项的字数相差不超过 20% |
| 结构一致 | 都用名词短语，或都用完整句子，不要混 |
| 禁止荒谬项 | 不出现"替代操作系统内核""管理照片"这类一眼假的选项 |
| 禁止通用项 | 不用"以上都对""以上都不对""以上都可能" |
| 每项都有来源 | 每个错误选项都对应一个真实存在的误解，不能随手编 |
| 位置随机 | 正确答案均匀分布，不超过连对两题在同一位置 |

**不合规**（一眼可排除）：

> 推理引擎的作用是什么？
> A. 运行已训练好的模型
> B. 保存用户的照片和文件
> C. 替代操作系统内核
> D. 为电脑安装办公软件

**合规**（每项都像对的）：

> 推理引擎在整条链路里负责哪一段？
> A. 把训练数据整理成可用的样本
> B. 加载已训练模型并执行其中的计算
> C. 把模型文件压缩到适合端侧的体积
> D. 决定模型在目标硬件上用哪种精度

四项都是真实存在的环节，只有 B 是推理引擎的职责。A 是数据处理，C 是量化，D 是量化策略选择。

### 3. 每题必须带参考来源

答题后，无论对错，都显示三样东西：

```
正确答案：B
解析：……（为什么 B 对，其他项各自是什么）
来源：docs-chip · key_stone/k3/k3_docs/k3_ds.md · 2.1.2 A100
```

规则：

- 来源写到**章节号**，不能只写文件名。
- 解析要说明**每个错误选项属于什么**，不只解释正确答案。
- 多选题的解析逐项说明为什么选、为什么不选。

### 4. 自评按知识点拆

不要问"这一讲懂了吗"。一个概念一行：

```
X100 与 A100 的区别    [懂了] [有疑问] [没懂]
内存带宽为什么是瓶颈    [懂了] [有疑问] [没懂]
```

自评只记录在本地页面，不参与判分，也不作为继续学习的门槛。

### 5. 每题必须内嵌回看原文

答题后除了来源，还要直接显示**从课文抽出的 2–3 句原文**，正好解决这个题需要的那几句。

不好：`来源：第三课第三节`

好：

```
回看这段
18W 是最轻负载，35W 是最重负载。按 18W 设计、再留 20% 也才
21.6W，离 35W 差得远。正确做法是以 35W 为设计点，再往上留余量。
```

规则：

- 片段必须来自课文里真实存在的句子，不能现场改写。
- 只给这题需要的部分，不要整节复制。
- 数据字段命名为 `rv`，紧跟 `src` 之后。

**理由**：读者点完就想核对，让他翻文件就是打断。

### 6. 结果页必须有「需回看」优先级清单

按下面顺序排，不要混在一起：

| 优先级 | 条件 | 为什么排这里 |
|---|---|---|
| 1 | 答错 **且** 对应自评项标了「懂了」 | 认知偏差最危险，自己不知道 |
| 2 | 答错 | 明确不会 |
| 3 | 自评「没懂」或「有疑问」 | 自己知道，但答对了也要巩固 |

规则：

- 用 `sai` 字段把每道题映射到自评项编号。**不能靠题号对齐**（题号与自评行号不一一对应）。
- 自评变化后清单要重新排序，不能只在答完时算一次。
- 全对时显示「不需要回看」，不要留空。

### 7. 跨次错误计数与讲解重写阈值

用 `localStorage` 记住每题错了多少次，key 用 `<模块名>.history`。

| 错次 | 提示 |
|---|---|
| 1 次 | 正常列出，「错第 1 次」 |
| **2 次及以上** | 显示「⚠ 同一题已错 N 次 —— 更可能是这一节的讲解需要换个说法，而不是再读一遍」 |

**这条规则的意义**：把「学习者没懂」和「教材讲得不好」分开。同一题错两次，先怀疑讲解，不要让对方再读同样的文字。

清空策略：

- 「重做」只清页面状态，**不清历史**（否则计数失去意义）。
- 另设「清除历史」入口，供需要时手动重置。

### 8. 结果页必须有「复制诊断摘要」

一个按钮，把本次结果生成可粘贴的短文本：

```
M1 测验 第 2 次 | 12/14
错：Q7 功耗区间（错第 2 次）、Q13 算力比较（错第 1 次）
自评疑问：K3 四种形态（有疑问）、规格表版本（没懂）
矛盾（标懂了但答错）：Q7
建议重写讲解：Q7
```

包含五项：**第几次、错题及错次、自评疑问、矛盾项、建议重写项**。

**理由**：助教不主动介入，只在收到消息时处理。有这个按钮，学习者一条消息就能让助教直接改课程，不用再描述错在哪里。

复制实现要有兜底：`navigator.clipboard` 在 `file://` 下可能不可用，需回退到 `document.execCommand("copy")`。

### 9. 从模板开始，不要从头写

复制 `spacemit/study/quiz/_template.html` 为 `<模块>-recap.html`，只填 `DATA` 数组。

模板已固定：CSS、判分逻辑、锁定、键盘操作、内嵌回看原文、三级优先级清单、跨次计数、复制诊断、重做策略。

**必须替换的占位符**：`__MODULE__`、`__MODULE_TITLE__`、`__MODULE_KEY__`、`__N_BASIC__`、`__N_TRAP__`、`__N_SA__`、`__N_TOTAL__`、`__LESSON_LINKS__`。

不要改交互逻辑。如果确实需要改，先改模板，再让它继承到各模块——否则各模块行为会漂移，跨模块诊断也拼不起来。

详细字段说明见 `spacemit/study/quiz/README.md`。

### 10. 测验页面的交付要求
#### 基础要求

- 本地单个 HTML 文件，不依赖网络。
- 点击选项立即判分，已答题目锁定，不重复计分。
- 答完显示总分与分组统计。
- 提供「重做」，清空所有状态（但保留历史计数）。
- 键盘可操作（Tab 聚焦、Enter/空格 触发）。
- 每题字段包含：`q`、`opts`、`a`、`e`、`wrong`（逐项）、`src`、`rv`、`sai`。

#### 题目数量与覆盖

| 规则 | 说明 |
|---|---|
| 每题一个自评项 | 每条自评必须至少有一道题对应，否则删掉该自评项 |
| 每篇课 4–5 题 | 三课一模块约 12–15 题 |
| 上限 15 题 | 再多就是同一考点的变体，读者会跳读 |
| 想要巩固就重做 | 同一套题隔几天再做，比加题有效（间隔效应） |

### 11. 报告学习结果时的口径

- 不把分数当掌握程度的证明。
- 分清三种状态：**答错**、**答对但自评有疑问**、**答错却自评「懂了」**。第三类最需要单独指出来。
- 助教只在收到学习者消息时介入，不要声称「自动跟进」。

## 检查清单

交付一篇课之前，逐条过：

- [ ] 末尾有参考来源表，路径和章节真实可查
- [ ] 没有超过 40 字的句子
- [ ] 没有超过 4 句的段落
- [ ] 每个术语首次出现带英文和缩写全称
- [ ] 每个数字带条件
- [ ] 有 3 个快速自测问句

交付一份测验之前：

- [ ] 三段结构齐全，题量符合
- [ ] 没有荒谬选项、没有"以上都对"
- [ ] 选项字数接近，结构一致
- [ ] 每题答题后显示答案、解析、来源章节
- [ ] 解析覆盖每个错误选项
- [ ] 自评按知识点拆行
- [ ] 判分、锁定、统计、重做实测通过

### 交付前必须实测的场景

逐项跑过，不要只跑正常路径：

- [ ] 全部答对
- [ ] 部分答错
- [ ] 同一题连错两次（验证重写提示）
- [ ] 答错且自评标「懂了」（验证优先级 1）
- [ ] 答错且自评标「没懂」
- [ ] 自评从「懂了」改成「没懂」（验证清单重排）
- [ ] 点击复制诊断摘要（验证内容与兜底）
- [ ] 重做（验证页面清空、历史保留）

实测结果写进 `HANDOFF.md`：哪些通过、哪些没验证、修过什么缺陷。
