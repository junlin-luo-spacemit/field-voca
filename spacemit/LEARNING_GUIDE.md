# SpacemiT 学习指南（技术写作视角）

> **写给谁**：懂基本计算机概念（CPU、内存、操作系统），但对芯片行业是新手的技术写作/文档工程师。
> **解决什么问题**：芯片知识无边无际，但**写文档需要的只是其中一小块**。本指南帮你划出这条线，只学用得上的部分。
> **不写给谁**：不需要懂寄存器时序、不需要会写驱动、不需要做架构设计 —— 那是工程师的地盘。

---

## 0. 先想清楚一件事：你和工程师的学习目标不一样

新手最容易犯的错误是：抓着一份 Datasheet 从头啃。结果看了 200 页，还是不知道怎么写一个"K1 快速上手"。

**因为写作需要的是"能解释清楚功能"，不是"能实现功能"。**

| | 工程师学什么 | 你要学什么 |
|---|---|---|
| 目标 | 让芯片按预期工作 | 让读者看懂芯片能做什么 |
| 深度 | 精确到寄存器位、时序图、电气参数 | 功能层面：这块是干嘛的、解决什么问题 |
| 关键能力 | 计算、调试、验证 | 判断准确性、组织信息、统一术语 |
| 判断标准 | "能跑通" | "读者不会误解" |

**一个具体例子。** 文档里写 "PCIe Gen3 x4"，你需要知道的是：

- ✅ **必要**：PCIe 是高速外设接口，Gen3 x4 表示第三代、4 条通道，用来接 SSD 或网卡 —— 够写产品简介了
- ⬜ **可选**：Gen3 单通道 8 GT/s，x4 合计约 32 GT/s —— 写规格表时核对用
- ❌ **可跳过**：128b/130b 编码、链路训练状态机 —— 除非官方文档明确要求你解释

> **你的核心竞争力不是"懂多少技术"，而是"知道哪些需要核实、哪些可以直接引用"。** 这一点贯穿整个指南。

## 1. 知识分三层：哪些必须懂，哪些可以跳过

把每个概念放进下面三层，就知道该花多少时间。

### 🟥 第一层：必须懂（不能在被问到时说不清）

决定你能不能写出准确的文档。

| 概念 | 为什么必须懂 | 学到什么程度 |
|---|---|---|
| **SoC** / 系统级芯片 | SpacemiT 所有产品的基本形态 | 能说清"一颗芯片里集成了 CPU、AI 加速、GPU、内存控制器、I/O" |
| **CPU 核心**（X60/X100） | 所有性能描述的基础 | 知道它是 RISC-V 架构、多核、有大核小核之分 |
| **RISC-V** | SpacemiT 芯片的指令集基础 | 知道"指令集 = CPU 能听懂的语言"，和 ARM/x86 并列 |
| **内存层次**（L1/L2/LPDDR） | 规格表里反复出现 | 知道"越靠近 CPU 越快越小越贵"，能读懂规格表里的数字 |
| **AI 加速 / Matrix Extension** | SpacemiT 的差异化卖点 | 知道"专用硬件做矩阵运算，比 CPU 快很多" |
| **TOPS / 算力** | 产品宣传的核心数字 | 知道它是 AI 算力单位，能和竞品对比 |
| **BSP / SDK / 工具链** | 软件文档全建立在这上面 | 知道三者分别是什么、什么关系 |

### 🟨 第二层：看得懂就行（写的时候照抄，不用理解原理）

遇到这些内容，你的任务是**准确搬运和一致表达**，不是理解。

- 寄存器地址、位域定义 → 照抄表格，核对数字
- 电气参数（电压、电流、温度范围）→ 照抄，注意单位和条件
- 时序参数（setup/hold、延迟 ns）→ 照抄，保留原始表格
- 引脚定义、封装尺寸 → 照抄
- 协议帧格式 → 照抄结构图

> **写作原则**：这类内容出错 99% 不是因为不懂，而是因为**抄错、单位漏了、条件没写**。核对比理解重要。

### ⬜ 第三层：可以跳过（除非哪天工作真的需要）

- CPU 微架构细节：流水线级数、分支预测算法、乱序执行窗口
- 电路与物理：工艺节点细节、功耗仿真、信号完整性
- 编译器内部：寄存器分配、指令调度算法
- 内核驱动实现：中断处理注册、DMA 映射细节

看到这些不用焦虑 —— **不认识它们不影响你写出好文档**，就像写菜谱不需要懂分子料理。

## 2. 学习路径：按你手上的任务选，不要按文档分类学

你写的内容是混合的，所以**按任务驱动学习**最省时间。每次接到任务，先查下表。

| 你要写的文档 | 先学这些（按顺序） | 大概时间 |
|---|---|---|
| **产品简介 / Brief** | SoC → CPU 核心 → AI 算力 → 内存规格 → 竞品对比 | 3–4 小时 |
| **规格表 / Datasheet 摘编** | 上面的内容 + 第二层"照抄清单" + 单位与条件规范 | 2 小时（主要是核对练习） |
| **快速上手 / Getting Started** | BSP/SDK 概念 → 烧录流程 → 板卡形态 → 常见问题 | 4–5 小时 |
| **开发指南（SDK、工具链）** | 工具链概念 → 交叉编译原理 → SDK 组成 | 5–6 小时 |
| **翻译（中→英）** | 术语对照表 → 术语一致性检查清单 → 中英句式差异 | 2 小时（然后边做边积累） |

### 开始前的 30 分钟（所有人必做）

1. 读 [[概念地图]] —— 建立"SpacemiT 是什么公司、做什么芯片"的整体印象。**这是全库最重要的一页**，读完再来。
2. 读 [[跨厂商术语对照表]] 的"计算核心"一节 —— 如果你有 NVIDIA/ARM 的底子，这里能帮你把已知概念直接挂到新体系上。
3. 打开 [[官方文档结构地图]] —— 知道官方文档是怎么分类的，你就知道自己的工作范围在哪。

## 3. 分阶段学习计划

按这个顺序走，每阶段结束都有明确产出。**不要跳阶段**，后面的内容建立在前面的基础上。

### 阶段 1：建立全局认知（1–2 小时）

**目标**：能用自己的话说清"SpacemiT 是做什么的"。

| 读什么 | 得到什么 |
|---|---|
| [[概念地图]] | 五个层次：IP 核心 → SoC → 软件栈 → 产品 → 应用 |
| [[HOME\|SpacemiT 首页]] | 全库导航，知道有什么可用 |
| [[hardware/products/K1]] 概述部分 | 一个真实产品的样子 |

**产出**：写 3–5 句话总结"SpacemiT 做什么芯片、卖给谁"。写不出来就回去重读。

---

### 阶段 2：硬件基础（4–6 小时）

**目标**：能读懂产品规格表，能判断哪些参数需要核实。

| 顺序 | 内容 | 读什么 | 学到什么程度 |
|---|---|---|---|
| 2.1 | SoC 概念 | [[atoms/SoC]] | 能解释"为什么叫系统级芯片" |
| 2.2 | CPU 核心（Key Stone） | [[atoms/X60-Core]]、[[atoms/X100-Core]] | X60（K1）和 X100（K3）的区别 |
| 2.3 | CPU 核心（Vital Stone） | [[hardware/products/V100]] | V100 服务器级 CPU（46 核，昆明湖 V2R2 + X100） |
| 2.4 | AI 加速核心 | [[atoms/A100-AI-Core]]、[[ai/AI-Architecture]] | K1/K3 的 AI 算力来源，同构融合技术 |
| 2.5 | 矩阵扩展 | [[atoms/Matrix-Extension]] | 知道矩阵扩展是做什么的，为什么能提速 |
| 2.6 | 内存 | [[atoms/HBM]]、[[hardware/vocabulary]] 内存一节 | 分清 LPDDR 和 HBM 的定位差异 |
| 2.7 | 电源管理 | [[atoms/PMIC]] | 知道 PMIC 是配套芯片，不是主芯片 |
| 2.8 | 产品对比 | [[hardware/products/K1]]、[[hardware/products/K3]]、[[hardware/products/V100]] | K1（边缘）vs K3（边缘高性能）vs V100（数据中心） |

**产出**：拿 K1、K3、V100 的规格表，列出**你不敢确定含义的 5 个术语**。然后逐个查 —— 这就是你真正的知识缺口，比从头学高效得多。

---

### 阶段 3：RISC-V 基础（选学，按需 4–8 小时）

**目标**：知道 RISC-V 是什么，能看懂文档里出现的 RISC-V 术语。

> **重要**：你**不需要**系统学 RISC-V。SpacemiT 产品是 RISC-V 芯片，但你的工作是写文档，不是写汇编。
> **只在你需要解释"为什么选 RISC-V"、或文档里大量出现 RISC-V 术语时，才走这一步。**

**最小必要路径**（只读这 3 课）：

| 顺序 | 课程 | 为什么读 |
|---|---|---|
| 3.1 | [[../riscv/learning_path/01-计算机与RISC-V入门]] | 搞清 CPU、指令、寄存器、内存的关系 |
| 3.2 | [[../riscv/learning_path/02-RV32I基础指令]] | 知道"指令集"具体长什么样（读懂即可，不用记） |
| 3.3 | [[../riscv/learning_path/07-标准扩展学习]] | 理解 M/A/V 扩展 —— **V（向量）和 Matrix Extension 直接相关** |

**跳过**：[[../riscv/learning_path/05-特权架构入门]]、[[../riscv/learning_path/06-虚拟内存与操作系统]]、[[../riscv/learning_path/08-CPU微架构入门]] —— 除非工作明确需要。

**产出**：能解释"RV64GCVB"这串字母的大概含义（知道它是"64 位 + 一组扩展"就够）。

---

### 阶段 4：软件栈（4–6 小时）

**目标**：能写快速上手文档，能解释"芯片怎么跑起程序"。

这是新手最容易卡住的地方，因为芯片文档里软件名词密度极高。理清这条链路就好办了：

```
裸芯片 → 需要引导程序（Boot ROM → U-Boot） → 需要操作系统（Bianbu / Buildroot）
      → 需要驱动和库（SDK / BSP） → 需要开发工具（交叉编译工具链 / 烧录 / 调试）
```

| 顺序 | 内容 | 读什么 |
|---|---|---|
| 4.1 | OS 与发行版 | [[software/Bianbu]]、[[software/Buildroot]]、[[software/OpenWrt]] |
| 4.2 | SDK / BSP | [[software/SDK]] |
| 4.3 | 交叉编译 | [[tools/Cross-Compilation-Toolchain]] |
| 4.4 | 烧录与调试 | [[tools/Flashing-Tool]]、[[tools/JTAG-Debugging]] |
| 4.5 | 集成开发环境 | [[tools/SpacemiT-Studio]] |

**必懂的一个概念：交叉编译（Cross Compilation）**

你的电脑是 x86，芯片是 RISC-V —— **指令不同，程序不能直接用**。交叉编译就是"在 A 架构上，编译出 B 架构能跑的程序"。工具链名字 `riscv64-unknown-linux-gnu-gcc` 就是这个意思：目标架构是 riscv64。

**产出**：画一张从"插上电源"到"程序跑起来"的流程图，标出每一步需要的软件。

---

### 阶段 5：AI 栈（3–5 小时）

**目标**：能写 AI 相关文档，不会把概念搞混。

| 顺序 | 内容 | 读什么 |
|---|---|---|
| 5.1 | AI 平台全貌 | [[ai/AI-Platform]] |
| 5.2 | AI SDK | [[ai/AI-SDK]] |
| 5.3 | LLM 推理 | [[ai/LLM-SDK]] |
| 5.4 | 开源框架 | [[ai/LangChain]]、[[ai/Ollama]] |

**新手最容易混的两组概念**：

- **训练（Training）vs 推理（Inference）** —— 训练是"教模型"，推理是"模型回答问题"。SpacemiT 芯片主打**推理**（边缘设备上跑模型），不是训练。
- **模型（Model）vs 框架（Framework）vs 运行时（Runtime）** —— 模型是数据和参数，框架是写模型的工具（LangChain），运行时是让模型跑起来的程序（Ollama）。

**产出**：能用一句话说清"K3 能在本地跑 30B 大模型"是什么意思（K1 可运行 0.5B-1B 模型，V100 集群可跑 100B+ 超大模型）。

**Key Stone vs Vital Stone 对比：**
- **Key Stone（K1/K3）** — 边缘 AI 推理，带专用 AI 加速核心（2-60 TOPS）
- **Vital Stone（V100）** — 数据中心通用计算，无专用 AI 核心，搭配 GPU 卡做 AI 训练/推理

## 4. 写作专用基本功（这部分才是你的专业能力）

技术知识够用就行，但下面三项是**技术写作和翻译的核心手艺**，值得专门练。

### 4.1 术语一致性

同一个概念在一份文档里必须始终用同一个词。检查清单在 [[术语规范检查清单]]。

常见错误：

| ❌ 不一致 | ✅ 统一 |
|---|---|
| 有时写"处理器"，有时写"芯片" | 全文统一，首次出现标注英文 |
| 有时写"烧录"，有时写"刷写" | 择一，或按官方文档用词 |
| "AI 算力 2 TOPS" / "2TOPS 的 AI 性能" | 统一表述格式 |

**做法**：开工前先建一张本文档的术语表（10–20 个词），写作过程中持续补充，交付前用查找功能核对。

### 4.2 中英术语处理

你写中英混合内容，规则要提前定死：

- **首次出现**：中文（English）—— 例：交叉编译（Cross Compilation）
- **之后**：只用一种，别来回切换
- **专有名词不翻译**：Bianbu、Buildroot、K1、X60 保持原样
- **缩写首次展开**：SoC（System on Chip）
- **已有官方译名的跟随官方**，别自己发明

参考：[[跨厂商术语对照表]] 记录了同一概念在各家的叫法，是判断"该用哪个词"的依据。

### 4.3 准确性优先于流畅

芯片文档写错一个数字，可能导致客户烧坏板子。养成三个习惯：

1. **所有数字都要有来源** —— 标注出处（哪份文档、哪一页、哪个版本）
2. **条件和单位不能省** —— "支持 8K" 不够，要写"8K@30fps 解码"
3. **不确定的标注待确认** —— 写 `[待确认]`，不要猜。**宁可不写，不要写错。**

## 5. 常见新手陷阱（踩过的坑，提前知道）

| 陷阱 | 表现 | 怎么避开 |
|---|---|---|
| **陷入资料学不完的焦虑** | 觉得要把所有文档读完才能开始写 | 只学当前任务需要的。**任务驱动 > 系统学习** |
| **把"看懂"当成"懂了"** | 读的时候点头，写的时候卡住 | 每学完一节，用自己的话写 3 句总结 |
| **忽略单位与条件** | 抄规格时漏掉 "@ 2.5GHz" "典型值" | 见到数字就问：什么条件下？典型值还是最大值？ |
| **术语自己发明** | 官方叫"矩阵扩展"，你写成"矩阵加速单元" | 跟官方文档用词，别"优化"专有名词 |
| **混淆代际和型号** | 把 K1 的参数写到 K3 文档里 | 每个产品单独开一页对照，写前确认型号 |
| **不敢问** | 不确定的硬猜 | 标 `[待确认]` 提给工程师 —— **这是专业，不是无知** |

## 6. 自检清单

学完任一阶段，用这些题目检查。**答不上来就是还没学会，回去补**。

### 阶段 1–2（硬件）
- [ ] 能用一句话说清 SpacemiT 做什么
- [ ] 能解释 SoC 和单独 CPU 芯片的区别
- [ ] 能说清 K1 和 K3 的定位差异（哪个面向什么场景）
- [ ] 能读懂 TOPS 是什么意思，为什么它不等于"性能一定强"
- [ ] 看到 LPDDR5-6400 知道它在描述什么
- [ ] 能说出 PMIC 在系统里起什么作用

### 阶段 3（RISC-V）
- [ ] 能解释"指令集"是什么，为什么 ARM 和 RISC-V 不能混跑
- [ ] 知道 RV64 的含义
- [ ] 能说出向量扩展（V）和 Matrix Extension 的关系

### 阶段 4（软件栈）
- [ ] 能解释交叉编译为什么必须存在
- [ ] 能说清 BSP、SDK、工具链三者的关系
- [ ] 能画出"通电 → 系统启动 → 程序运行"的链路
- [ ] 知道烧录（Flashing）和调试（Debugging）的区别

### 阶段 5（AI）
- [ ] 能区分训练和推理
- [ ] 能说清 Ollama、LangChain、模型三者的角色
- [ ] 知道"本地推理"为什么对边缘设备重要

## 7. 学习记录

每学一段就在 [[学习记录]] 里记一行：学了什么、理解了什么、还卡在哪。

这个记录有两个用途：
1. **帮你复习** —— 一周后回看，知道自己的盲区
2. **变成写作素材** —— 你卡住的地方，正是读者也会卡住的地方。**这些就是你写"常见问题"和"概念说明"的原始材料**

> 对技术写作者来说，"新手期的困惑"是最有价值的资产 —— 一旦你变成老手，就再也想不起来当初哪里不懂了。趁现在记下来。
