# 跨厂商术语对照表 (Cross-Vendor Terminology Mapping)

> 目的：当你在学习 **NVIDIA / RISC-V / AMD / ARM / Intel / Qualcomm** 等厂商文档时，能快速找到"这个概念在 SpacemiT 里叫什么、有什么异同"。  
> 更新原则：每次学到一个新的外部术语，就在这里补一条对照记录，积少成多形成完整映射。  
> 支持厂商：目前已覆盖 NVIDIA、RISC-V、ARM；**AMD、Intel、Qualcomm 等待后续补充**。

---

## 如何使用这个表

| 列名 | 说明 |
|------|------|
| **外部术语** | 其他厂商的官方术语（明确标注来自哪家厂商）|
| **SpacemiT 对应** | 在 SpacemiT 文档/产品里的对应概念（可能是同名、改名、或"无对应但有替代方案"） |
| **相同点** | 功能/原理上的共通之处 |
| **关键差异** | 规格/实现/应用场景的核心区别 |
| **何时参考外部术语** | 什么情况下学习外部厂商这个概念能帮到 SpacemiT 文档 |

**颜色图例**（在支持 Obsidian 的环境中可用）：
- 🟢 **完全对应**：概念几乎一致，直接参考即可
- 🟡 **部分对应**：有对应物但实现方式或规格不同
- 🔴 **无直接对应**：SpacemiT 用不同方案实现同类需求

**厂商缩写**：
- `[NV]` = NVIDIA
- `[RV]` = RISC-V 生态（SiFive / Andes / T-Head 等）
- `[ARM]` = ARM Holdings
- `[AMD]` = AMD（待补充）
- `[INTC]` = Intel（待补充）
- `[QCOM]` = Qualcomm（待补充）

## 计算核心 (Compute Cores)

### CPU 核心

| 外部术语 | 厂商 | SpacemiT 对应 | 🟢🟡🔴 | 相同点 | 关键差异 | 何时参考 |
|---------|------|--------------|--------|--------|---------|---------|
| **ARM Cortex-A55** | `[ARM]` | [[X60-Core]] | 🟡 | 都是面向高能效的应用处理器核心 | X60 是 RISC-V 架构（RV64GCVB），Cortex-A55 是 ARMv8.2-A；X60 带可选 AI 扩展指令 | 对比功耗/性能曲线、缓存配置时 |
| **ARM Cortex-A76** | `[ARM]` | [[X100-Core]] | 🟡 | 都是高性能大核，面向服务器/旗舰移动设备 | X100 是 RISC-V，A76 是 ARMv8.2-A；X100 通常与 A100 AI 核心配对 | 对比单核性能、SPEC 跑分时 |
| **RISC-V SiFive U74** | `[RV]` SiFive | [[X60-Core]] | 🟡 | 都是 64-bit RISC-V 应用核心 | X60 可能有 SpacemiT 专有的 AI 扩展指令（非标准 RVV）| 学习标准 RISC-V 指令集作为基础 |
| **NVIDIA SM (Streaming Multiprocessor)** | `[NV]` | 无直接对应（CPU 与 GPU 架构不同）| 🔴 | 都是"可编程的并行计算单元" | SM 是 GPU 架构（SIMT 模型，面向数千个轻量线程），X60/X100 是标量 CPU（面向复杂控制流）| 理解并行编程思想时参考 SM，但实现机制完全不同 |
| **AMD Zen 4 Core** | `[AMD]` | [[X100-Core]] | 🟡 | 都是高性能 CPU 核心 | Zen 4 是 x86-64 架构，X100 是 RISC-V；Zen 4 功耗/算力更高（桌面/服务器），X100 面向边缘 | （待补充：对比 IPC、缓存层次、功耗包络时）|

### AI 加速核心

| 外部术语 | 厂商 | SpacemiT 对应 | 🟢🟡🔴 | 相同点 | 关键差异 | 何时参考 |
|---------|------|--------------|--------|--------|---------|---------|
| **NVIDIA Tensor Core** | NVIDIA | [[A100-AI-Core]]（K3 专属）<br>X60 AI 扩展（K1 Cluster0）| 🟡 | 都是矩阵乘/卷积的专用硬件加速器 | Tensor Core 支持 FP64/TF32/FP16/BF16/INT8/INT4；SpacemiT A100 支持 BF16/FP16/FP8/INT8/INT4（无 FP64/TF32）；Tensor Core 集成在 SM 内，A100 是独立核心 | 对比 TOPS 算力、支持的数据类型、矩阵尺寸限制时 |
| **Google TPU** | Google | [[A100-AI-Core]] | 🟡 | 都是专为深度学习设计的 ASIC | TPU 是云端/数据中心方案，A100 面向边缘；TPU 有专有 XLA 编译器，A100 用标准 RISC-V 工具链 + AI SDK | 学习 AI 芯片的架构思路（systolic array vs 其他）时 |
| **ARM Ethos-U NPU** | ARM | [[A100-AI-Core]] | 🟢 | 都是嵌入式/边缘 AI 加速器，功耗优先于峰值算力 | Ethos-U 系列（U55/U65）TOPS 范围 0.5-2；A100 (8核) 可达 ~60 TOPS（但 K1 Cluster0 AI 扩展只有 ~2 TOPS）| 对比边缘 AI 芯片的功耗/算力平衡点时 |

### GPU

| 外部术语 | 厂商 | SpacemiT 对应 | 🟢🟡🔴 | 相同点 | 关键差异 | 何时参考 |
|---------|------|--------------|--------|--------|---------|---------|
| **ARM Mali-G78** | ARM | IMG BXE-2-32（K1）<br>IMG BXE-4-64（K3）| 🟡 | 都是移动/嵌入式 GPU，支持 Vulkan/OpenCL/OpenGL ES | Mali-G78 峰值算力更高（旗舰手机 SoC），BXE 系列更侧重功耗与 OpenCL 3.0 支持 | 对比 GPU 规格、驱动成熟度时 |
| **NVIDIA GPU (H100/A100)** | NVIDIA | IMG BXE 系列（仅图形/通用计算）<br>A100 AI Core（AI 专用）| 🔴 | SpacemiT 用"GPU + 专用 AI 核心"的分离式设计，NVIDIA 用"统一 GPU 架构"（Tensor Core 集成在 SM 内）| NVIDIA GPU 可同时做图形/AI/科学计算；SpacemiT 分工更明确（BXE 做图形，A100 做 AI）| 学习 GPU 通用计算（GPGPU）概念时，但实现路径不同 |

## 内存与存储 (Memory & Storage)

| 外部术语 | 厂商 | SpacemiT 对应 | 🟢🟡🔴 | 相同点 | 关键差异 | 何时参考 |
|---------|------|--------------|--------|--------|---------|---------|
| **HBM3 (High Bandwidth Memory)** | NVIDIA / SK Hynix | 🔴 **K1/K3 均未采用**<br>替代方案：LPDDR4x/5 | 🔴 | 都是芯片主内存 | HBM3 带宽 3+ TB/s，功耗高，成本极高（数据中心 GPU）；LPDDR5-6400 带宽 ~51 GB/s，成本低，功耗低（移动/边缘）| 对比"为何 SpacemiT 不用 HBM"时的成本/功耗/带宽取舍 |
| **GDDR6X** | NVIDIA / Micron | 🔴 **未采用** | 🔴 | 都是高速 DRAM | GDDR6X 用于消费级 GPU（RTX 4090），带宽 ~1 TB/s；SpacemiT 用 LPDDR 系列（移动场景优先）| 理解不同内存类型的应用场景时 |
| **LPDDR5-6400** | JEDEC 标准 | K3 主内存（64-bit，最高 32 GB）| 🟢 | 标准 JEDEC 规格，跨厂商通用 | SpacemiT 实现与标准一致 | 查 LPDDR5 时序、电压等技术细节时，参考 JEDEC 官方文档即可 |
| **Shared Memory (CUDA)** | NVIDIA | [[RISC-V]] TCM (Tightly-Coupled Memory) | 🟡 | 都是核心附近的快速暂存内存（比 L1 更可控）| CUDA Shared Memory 在 SM 内，每个 block 独享；TCM 在 RISC-V 核心旁，软件管理地址映射 | 学习"如何用软件管理的快速内存优化性能"时 |

## 软件栈 (Software Stack)

| 外部术语 | 厂商 | SpacemiT 对应 | 🟢🟡🔴 | 相同点 | 关键差异 | 何时参考 |
|---------|------|--------------|--------|--------|---------|---------|
| **CUDA Toolkit** | NVIDIA | [[SDK]]（Buildroot/Bianbu/OpenHarmony/ROS2）| 🟡 | 都是"硬件 + 驱动 + 编译器 + 库 + 示例"的完整开发包 | CUDA 是专有生态（nvcc 编译器、cuDNN/cuBLAS 库）；SpacemiT SDK 基于开源工具链（GCC/LLVM + 标准 Linux）| 学习"如何组织一个完整 SDK"时的结构设计 |
| **TensorRT** | NVIDIA | [[AI-SDK]] / [[LLM-SDK]] | 🟡 | 都是深度学习推理优化引擎 | TensorRT 支持动态 shape、INT8/FP16 量化、插件扩展；SpacemiT AI SDK 功能待文档明确 | 对比推理优化手段（算子融合、量化）时 |
| **cuDNN** | NVIDIA | SpacemiT AI SDK 内置算子库（具体名称待确认）| 🟡 | 都是神经网络基础算子库（卷积、池化、归一化等）| cuDNN 有 20 年积累，高度优化；SpacemiT 算子库相对新 | 学习"常见 NN 算子的优化技巧"时 |
| **Linux for Tegra (L4T)** | NVIDIA | [[Bianbu]]（基于 Ubuntu 的 RISC-V 发行版）| 🟡 | 都是厂商定制的 Linux 发行版，预装驱动与 SDK | L4T 基于 Ubuntu for ARM；Bianbu 基于 Ubuntu for RISC-V | 学习"如何做一个芯片厂商的官方 Linux 发行版"时 |

## 待补充厂商清单

以下厂商计划后续补充对照条目（按优先级排序）：

1. **AMD** — 重点对照 Zen/RDNA 架构（CPU + GPU），AI 引擎（XDNA）

3. **Qualcomm** — 重点对照 Snapdragon（Kryo CPU + Adreno GPU + Hexagon NPU）移动平台

## 如何为这个表贡献新条目

1. **识别外部术语**：在学习 NVIDIA/RISC-V/ARM 文档时，遇到一个核心概念。
2. **查找 SpacemiT 对应**：在 `spacemit/atoms/` 或 `spacemit/atoms/products/` 里找有无对应词条。
3. **填写对照行**：按上述表格格式，补充"相同点""关键差异""何时参考"三列。
4. **更新日期**：在"更新日志"里记一笔。

**示例新增流程**（假设你刚学了 NVIDIA 的 CUDA Stream）：
- 在"软件栈"表格下新增一行：
  - 外部术语：`CUDA Stream`
  - SpacemiT 对应：`🔴 无直接对应（RISC-V 用标准 POSIX 线程 + DMA 控制）`
  - 相同点：都是"管理异步操作的机制"
  - 关键差异：CUDA Stream 是 GPU 专有抽象；RISC-V 用 CPU 线程 + 硬件 DMA 通道组合实现
  - 何时参考：学习"如何设计异步 API"时的抽象思路
