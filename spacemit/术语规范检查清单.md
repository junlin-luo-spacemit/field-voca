# SpacemiT 术语规范检查清单 (Terminology Style Guide)

> 目的：作为 SpacemiT 文档专员审查中英文术语一致性的工作清单。  
> 使用方式：新建/修改词条前先看第 1 节的规则；定期用第 2 节的检查表抽查已有词条；第 3 节记录已发现但未修复的问题，逐条销项。

---

## 1. 命名规范（新建词条时遵守）

### 1.1 缩写型英文术语（SoC / HBM / IOMMU / PMIC 等）

**规则**：标题统一用 `英文全大写（中文全称）` 格式；正文"定义"首句必须复现中文全称，不能只展开英文全称就结束。

```markdown
✅ 正确：# IOMMU（输入输出内存管理单元）
   定义：IOMMU（Input-Output Memory Management Unit，输入输出内存管理单元）负责...

❌ 错误：# IOMMU
   定义：IOMMU 全称 Input–Output Memory Management Unit，负责...（缺中文全称，且用了不一致的破折号）
```

### 1.2 SDK / 平台类概念

**规则**：保持"全大写英文 + 空格"命名（如 `AI SDK`、`LLM SDK`），定义首句给出中文译名（"软件开发套件"）。此规则已在现有词条中执行良好，继续沿用。

### 1.3 工具类英文标题（Flashing Tool / Trace Tool / JTAG Debugging）

**规则**：标题保留英文，但必须在标题或定义首句补上标准中文译名括注。

```markdown
✅ 正确：# Flashing Tool（烧录工具）
❌ 错误：# Flashing Tool  （定义里也从未出现"烧录工具"）
```

### 1.4 "CPU 核"相关术语 — 全库统一为"核心"

**规则**：不用"内核"（容易与操作系统 kernel 混淆），不用单字"核"（偏口语化）。统一译为**核心**。

| 场景 | ✅ 统一用法 | ❌ 避免用法 |
|------|-----------|-----------|
| CPU core | X60 核心 / 8 个核心 | X60 内核 / 8 核 |
| AI core | A100 AI 核心 | A100 AI 内核 |

### 1.5 frontmatter tags 大小写

**规则**：纯英文缩写词条的 tag 保留原缩写大小写（`HBM`、`IOMMU`、`PMIC`、`ROS2`），与文件名/标题大小写完全一致，不转小写。

### 1.6 文件名 / tag / 标题三者的空格与连字符规则

**规则**：同一术语在文件名、frontmatter tag、一级标题三处必须使用**同一种**空格/连字符写法，二选一并全库统一：
- 方案 A：无空格连写（`ROS2`）
- 方案 B：带空格（`ROS 2`）

> 建议采用方案 A（无空格），因为文件系统路径和 wikilink 里带空格容易出错。

### 1.7 占位性/待核实内容不能写进"定义"小节

**规则**：如果术语的确切含义尚未从官方文档核实，不要把"疑为…需核实"这类调查笔记直接当作"定义"。应使用独立的"待核实"小节，"定义"小节留空或写"[待核实，见下方待核实说明]"。

```markdown
✅ 正确：
## 定义
[待核实]

## 待核实说明
`Bianbu` 疑为 SpacemiT 的操作系统/平台名称，需在官方文档中核实其具体角色。

❌ 错误：
## 定义
疑为 SpacemiT 文档中提及的操作系统或平台名称（需在官方文档中核实具体角色）。
```

## 2. 抽查检查表（定期审查已有词条时使用）

逐条词条检查时，按此表打勾：

- [ ] 标题的英文/中文格式是否符合上述 1.1-1.3 的规则
- [ ] "定义"小节首句是否包含规范中文译名
- [ ] 是否有"内核/核/核心"这类同概念多译法混用
- [ ] frontmatter tags 大小写是否与文件名/标题一致
- [ ] 文件名/tag/标题的空格连字符是否统一
- [ ] "定义"小节是否混入了"疑为…需核实"式占位文本
- [ ] 同一文件内部前后是否使用了不同译法（如"核内"又说"核规范"）

## 4. 修复优先级建议

1. **先做 1.4（CPU 核统一为"核心"）**——影响范围最广，涉及 K1/K3/X60-Core 等核心产品词条，直接影响文档专业度的第一印象
2. **再做 3.3（占位性内容分离）**——Bianbu/RV2768 目前是"猜测当定义"，风险最高（读者可能把猜测当成官方事实）
3. **然后做缩写型术语补中文译名**（IOMMU/Flashing-Tool/Trace-Tool/Design-Philosophy）
4. **最后统一 tags 大小写和文件命名规则**——影响面广但不涉及内容准确性，可以批量处理
