# 07 标准扩展学习

**前置阅读**：[[06-虚拟内存与操作系统|← 06 虚拟内存与操作系统]]

## 你要学什么

前面你学的 RV32I/RV64I 是**基础指令集**，只有最基本的操作（加减、取放、跳转）。

但有些任务需要特殊能力：乘除法、浮点运算、多核同步、向量处理。RISC-V 用**扩展（Extension）** 来提供这些能力。

### 为什么要学这个？

现在你已经掌握了核心知识，但看芯片规格时会遇到 RV64GC、RV32IMAC 这样的名字，不知道什么意思。

**这一章解决的问题：**
- M/A/F/D/C/V 这些字母代表什么？
- 什么场景需要哪些扩展？
- 怎么根据需求选择合适的芯片配置？

学完后，你就能看懂芯片规格，知道不同配置的差异。下一章会教微架构——为什么同样的指令集，性能差别巨大。

---

## 从生活例子开始

想象你买工具箱：

### 场景：选择工具

**基础工具箱**：锤子、螺丝刀、扳手（够日常使用）

**但遇到特殊任务：**
- 要钻孔 → 买电钻（M扩展：乘除法）
- 要精确测量 → 买卷尺（F/D扩展：浮点运算）
- 多人协作 → 买对讲机（A扩展：原子操作）
- 要批量处理 → 买传送带（V扩展：向量指令）
- 空间有限 → 买折叠工具（C扩展：压缩指令）

**你不需要一次买齐所有工具，按需选择。**

## RISC-V 扩展命名

RISC-V 用字母表示不同扩展：

| 扩展 | 全称 | 用途 | 常见场景 |
|------|------|------|----------|
| **I** | Integer | 基础整数运算 | 所有系统（必选） |
| **M** | Multiply/Divide | 乘法、除法 | 需要乘除运算 |
| **A** | Atomic | 原子操作 | 多核同步 |
| **F** | Float | 单精度浮点 | 科学计算 |
| **D** | Double | 双精度浮点 | 高精度计算 |
| **C** | Compressed | 压缩指令（16位） | 代码空间受限 |
| **V** | Vector | 向量指令 | AI、图像处理 |
| **Zicsr** | CSR | CSR 寄存器操作 | 系统编程 |
| **Zifencei** | Fence.i | 指令缓存同步 | 动态代码生成 |

**组合命名**：
- **RV32I** = 32位基础指令集
- **RV32IM** = 基础 + 乘除法
- **RV32GC** = 基础 + 通用扩展（G = IMAFD）+ 压缩指令
- **RV64GCV** = 64位 + 通用扩展 + 压缩 + 向量

## M 扩展：乘法和除法

### 问题：没有 M 扩展会怎样？

计算 `5 × 3` 需要用循环加法：

```asm
# 没有 M 扩展：用循环
li   x5, 5       # 被乘数
li   x6, 3       # 乘数
li   x7, 0       # 结果
loop:
    add  x7, x7, x5   # 累加
    addi x6, x6, -1   # 计数器减1
    bne  x6, x0, loop # 如果不为0，继续循环
# x7 = 15（需要3次循环）
```

**慢！而且代码长。**

### 有了 M 扩展：

```asm
li   x5, 5
li   x6, 3
mul  x7, x5, x6   # x7 = 5 × 3 = 15（一条指令）
```

**M 扩展指令：**

| 指令 | 意思 | 例子 |
|------|------|------|
| `mul` | 乘法（低位） | `mul x7, x5, x6` → x7 = (x5 × x6)的低32/64位 |
| `mulh` | 乘法（高位，有符号） | 处理溢出 |
| `div` | 除法 | `div x7, x5, x6` → x7 = x5 ÷ x6 |
| `rem` | 取余 | `rem x7, x5, x6` → x7 = x5 % x6 |

**什么时候需要 M 扩展？**
- 几乎所有实际应用（乘除太常用了）
- 嵌入式控制器、操作系统、应用程序

**什么时候可以不要？**
- 极简单的硬件逻辑控制（如LED控制器）
- 为了降低成本和功耗

## A 扩展：原子操作

### 问题：多核竞争

两个 CPU 核心同时修改同一个变量：

```c
// 两个核心同时执行
count = count + 1;
```

**可能的顺序：**
```
核心1: 读 count (值=10)
核心2: 读 count (值=10)
核心1: 写 count = 11
核心2: 写 count = 11  ← 错了！应该是12
```

**结果：丢失一次加法。**

### 有了 A 扩展：

```asm
# 原子加法：不会被打断
li   x6, 1
amoadd.w x5, x6, (x10)   # 原子地：x5 = *x10, *x10 += x6
```

**A 扩展指令：**

| 指令 | 意思 |
|------|------|
| `lr.w` / `sc.w` | Load-Reserved / Store-Conditional（配对使用） |
| `amoadd.w` | 原子加法 |
| `amoswap.w` | 原子交换 |
| `amoand.w` / `amoor.w` | 原子与/或 |

**什么时候需要 A 扩展？**
- 多核系统
- 操作系统内核（锁、信号量）
- 多线程应用

**什么时候可以不要？**
- 单核系统（没有竞争）

---

## F/D 扩展：浮点运算

### 问题：整数不能表示小数

```c
float pi = 3.14159;
float area = pi * r * r;
```

**用整数模拟浮点很慢很复杂。**

### 有了 F/D 扩展：

```asm
# F 扩展：单精度（32位）
flw   f0, 0(x10)      # 从内存加载浮点数
flw   f1, 4(x10)
fmul.s f2, f0, f1     # f2 = f0 × f1（浮点乘法）

# D 扩展：双精度（64位）
fld   f0, 0(x10)
fmul.d f2, f0, f1     # 双精度乘法
```

**新增 32 个浮点寄存器**：`f0` - `f31`

**什么时候需要 F/D 扩展？**
- 科学计算、工程仿真
- 3D图形、游戏
- 机器学习（部分场景）

**什么时候可以不要？**
- 纯整数应用（嵌入式控制、协议处理）

---

## C 扩展：压缩指令

### 问题：代码空间有限

标准指令都是 32 位（4字节），程序会占用很多内存。

### C 扩展：部分指令压缩成 16 位

```asm
# 标准指令（32位）
addi x5, x5, 4

# 压缩指令（16位）
c.addi x5, 4     # 功能相同，只占一半空间
```

**好处：**
- 代码大小减少 25-30%
- 指令缓存利用率更高
- 适合代码空间受限的嵌入式系统

**CPU 自动识别**：遇到 16 位指令，解码后执行。程序员不需要特别处理。

**什么时候需要 C 扩展？**
- 闪存/ROM 空间有限
- 嵌入式系统、IoT 设备

---

## V 扩展：向量指令

### 问题：一次只能处理一个数据

计算数组和：

```c
int sum = 0;
for (int i = 0; i < 1000; i++) {
    sum += array[i];  // 1000 次循环
}
```

### 有了 V 扩展：

```asm
# 一次处理 8/16/32 个元素（取决于向量长度）
vle32.v v0, (x10)     # 从内存加载一批数字到向量寄存器 v0
vadd.vv v2, v0, v1    # 向量加法：v2 = v0 + v1（一次算多个）
```

**向量寄存器**：`v0` - `v31`，每个可以存多个数据。

**什么时候需要 V 扩展？**
- AI/机器学习（矩阵运算）
- 图像/视频处理
- 科学计算（大规模数据）

**对比：**
- **标量（无V扩展）**：一次算一个数字
- **向量（有V扩展）**：一次算一批数字（快几倍到几十倍）

## 怎么选择扩展：决策树

```
你在做什么？
│
├─ 嵌入式控制（LED、电机）
│  → RV32I 或 RV32IMC
│
├─ 需要乘除法吗？
│  ├─ 是 → 加 M
│  └─ 否 → 只用 I
│
├─ 多核系统吗？
│  ├─ 是 → 加 A（原子操作）
│  └─ 否 → 不需要 A
│
├─ 需要浮点运算吗？
│  ├─ 单精度够 → 加 F
│  ├─ 双精度 → 加 F + D
│  └─ 不需要 → 不加
│
├─ 代码空间紧张吗？
│  ├─ 是 → 加 C（压缩指令）
│  └─ 否 → 不需要 C
│
└─ AI/图像/大数据处理？
   ├─ 是 → 加 V（向量）
   └─ 否 → 不需要 V
```

## 常见组合

| 配置 | 扩展 | 适合场景 |
|------|------|----------|
| **RV32I** | 只有基础指令 | 极简控制器 |
| **RV32IMC** | + 乘除 + 压缩 | 嵌入式系统（IoT） |
| **RV32GC** | I+M+A+F+D+C | 通用嵌入式 |
| **RV64GC** | 64位 + 通用 | Linux 系统、服务器 |
| **RV64GCV** | + 向量 | AI推理、数据中心 |

**G = IMAFD**（General，通用扩展的简写）

看到芯片规格：**RV64IMAFDC**

- 这是什么架构？（64位 RISC-V）
