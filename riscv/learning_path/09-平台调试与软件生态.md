## 你要学什么

前面学了指令、特权、虚拟内存，都是理论。现在要让代码真正跑起来。

**核心流程：写代码 → 编译 → 运行 → 调试 → 部署。**

### 为什么要学这个？

看懂汇编代码和自己写代码是两回事。就像看懂菜谱和真正做菜的区别。

**这一章解决的问题：**
- 怎么把 C 代码编译成 RISC-V 程序？
- 没有 RISC-V 硬件怎么运行？（模拟器）
- 程序出错怎么调试？（GDB）

学完后，你就能完整地开发 RISC-V 程序。最后一章会给你5个实践项目，把前面所有知识串联起来。

## 从生活例子开始

想象你排练一场话剧：

### 场景：从剧本到演出

1. **剧本**（C源代码）：编剧写的故事
2. **导演翻译**（编译器）：把剧本变成演员的动作指令
3. **排练厅**（模拟器）：先在排练厅练习，不用真舞台
4. **导演暂停**（调试器）：某个动作不对，暂停检查
5. **正式舞台**（开发板）：排练好了，上真舞台演出

**开发 RISC-V 程序也是这个流程。**

## 工具链：从源码到可执行文件

### 1. 编译器（Compiler）

**作用：把 C/C++ 代码翻译成 RISC-V 汇编/机器码。**

**常用工具：**
- **GCC**：`riscv64-unknown-elf-gcc`（裸机）/ `riscv64-linux-gnu-gcc`（Linux）
- **LLVM/Clang**：`clang --target=riscv64`

**例子：**

```c
// hello.c
int main() {
    int a = 5;
    int b = 3;
    int c = a + b;
    return c;
}
```

编译：
```bash
riscv64-unknown-elf-gcc -O2 -o hello.elf hello.c
```

生成的 `hello.elf` 包含 RISC-V 机器码。

**查看汇编：**
```bash
riscv64-unknown-elf-objdump -d hello.elf
```

输出：
```asm
<main>:
    li   a0, 8        # c = 8（编译器优化掉了计算）
    ret
```

---

### 2. 模拟器（Emulator）

**作用：在 x86 电脑上模拟 RISC-V CPU，不需要真硬件。**

**常用工具：**

| 工具 | 特点 | 用途 |
|------|------|------|
| **QEMU** | 全系统模拟，支持 Linux | 运行操作系统 |
| **Spike** | ISA级模拟器，精确但慢 | ISA验证、教学 |
| **Renode** | 多核/外设模拟 | 嵌入式系统开发 |

**例子：用 QEMU 运行**

```bash
# 模拟 RISC-V 64位 CPU，运行裸机程序
qemu-system-riscv64 -machine virt -bios none -kernel hello.elf -nographic
```

**QEMU 做了什么：**
1. 读取 `hello.elf`
2. 模拟 RISC-V CPU 执行指令
3. 模拟内存、设备
4. 输出结果

---

### 3. 调试器（Debugger）

**作用：暂停程序，查看寄存器、内存，单步执行。**

**工具：GDB（GNU Debugger）**

```bash
# 启动 QEMU，等待 GDB 连接
qemu-system-riscv64 -machine virt -kernel hello.elf -s -S

# 另一个终端，启动 GDB
riscv64-unknown-elf-gdb hello.elf
(gdb) target remote localhost:1234   # 连接 QEMU
(gdb) break main                     # 在 main 设置断点
(gdb) continue                       # 继续执行
(gdb) info registers                 # 查看寄存器
(gdb) step                           # 单步执行
(gdb) print a                        # 查看变量
```

**GDB 常用命令：**

| 命令 | 作用 |
|------|------|
| `break main` | 在 main 函数设置断点 |
| `continue` | 继续执行到断点 |
| `step` | 单步执行（进入函数） |
| `next` | 单步执行（跳过函数） |
| `info registers` | 查看所有寄存器 |
| `x/10x 0x1000` | 查看内存地址 0x1000 的10个字 |
| `print variable` | 查看变量值 |
| `backtrace` | 查看调用栈 |

### 4. 开发板（Real Hardware）

**作用：在真实 RISC-V 芯片上运行程序。**

**常见开发板：**

| 开发板 | 芯片 | 用途 |
|--------|------|------|
| **HiFive Unmatched** | SiFive U740 (RV64GC) | Linux开发 |
| **Milk-V Duo** | CV1800B (RV64GC) | 嵌入式Linux |
| **Sipeed Longan Nano** | GD32VF103 (RV32IMAC) | 裸机开发 |
| **BeagleV Ahead** | TH1520 (RV64GCV) | AI边缘计算 |

**通过串口连接：**
```bash
# 通过 UART 连接开发板
minicom -D /dev/ttyUSB0 -b 115200
```

## 完整开发流程

### 步骤1：写代码

```c
// blink.c - 裸机程序，点亮LED
#define LED_ADDR 0x10012000

int main() {
    volatile unsigned int *led = (unsigned int *)LED_ADDR;
    while (1) {
        *led = 1;  // 点亮
        for (int i = 0; i < 1000000; i++);  // 延时
        *led = 0;  // 熄灭
        for (int i = 0; i < 1000000; i++);
    }
    return 0;
}
```

### 步骤2：编译

```bash
riscv64-unknown-elf-gcc -march=rv64gc -mabi=lp64d -o blink.elf blink.c
```

**参数说明：**
- `-march=rv64gc`：目标架构（64位 + 通用扩展）
- `-mabi=lp64d`：ABI（调用约定）
- `-o blink.elf`：输出文件

### 步骤3：在 QEMU 运行

```bash
qemu-system-riscv64 -machine virt -kernel blink.elf -nographic
```

### 步骤4：调试

```bash
# 终端1：启动 QEMU，等待调试
qemu-system-riscv64 -machine virt -kernel blink.elf -s -S

# 终端2：GDB 调试
riscv64-unknown-elf-gdb blink.elf
(gdb) target remote :1234
(gdb) break main
(gdb) continue
(gdb) step
```

### 步骤5：部署到开发板

```bash
# 通过串口或 JTAG 烧录到开发板
openocd -f board/sipeed-longan-nano.cfg -c "program blink.elf verify reset exit"
```

## 第一个实验：Hello World

### 1. 安装工具链

```bash
# Ubuntu/Debian
sudo apt install gcc-riscv64-unknown-elf qemu-system-riscv64 gdb-multiarch

# 验证安装
riscv64-unknown-elf-gcc --version
qemu-system-riscv64 --version
```

### 2. 写代码

```c
// hello.c
#include <stdio.h>

int main() {
    printf("Hello, RISC-V!\n");
    return 0;
}
```

### 3. 编译

```bash
riscv64-unknown-elf-gcc -o hello.elf hello.c
```

### 4. 运行

```bash
qemu-riscv64 hello.elf
```

输出：
```
Hello, RISC-V!
```

### 5. 查看汇编

```bash
riscv64-unknown-elf-objdump -d hello.elf | less
```

找到 `main` 函数，看生成的 RISC-V 指令。

## 常见问题

### Q: QEMU 和 Spike 有什么区别？

- **QEMU**：快，支持设备，适合运行完整系统
- **Spike**：慢，但严格遵循 ISA 规范，适合验证指令

### Q: 裸机程序和 Linux 程序有什么区别？

- **裸机**：直接访问硬件，没有操作系统（需要自己管理中断、内存）
- **Linux**：通过系统调用访问硬件，操作系统管理一切

### Q: 怎么选开发板？

- **学习 Linux**：HiFive Unmatched, Milk-V Duo
- **嵌入式开发**：Sipeed Longan Nano
- **AI应用**：BeagleV Ahead（有向量扩展）
