# 03 汇编与程序执行

**前置阅读**：[[02-RV32I基础指令|← 02 RV32I基础指令]]

## 你要学什么

上一章你学了单个指令（`add`、`lw`、`beq`）。现在要学怎么把它们组合成程序。

**汇编就是 CPU 能听懂的命令清单。**

### 为什么要学这个？

认识单个汉字不等于能读文章。同样，认识单条指令不等于能读程序。

**这一章解决的问题：**
- CPU 怎么知道下一条执行哪条指令？
- 一段代码怎么一步步执行？
- 怎么跟踪寄存器的变化？

学完后，给你一段汇编，你就能说出每步发生了什么。下一章会教函数调用——代码模块之间怎么互相调用。

---

## 从生活例子开始

假设你跟朋友说："帮我做杯咖啡。"

朋友听懂了，但具体要做什么？拆开来看：

1. 拿杯子
2. 烧水
3. 放咖啡粉
4. 倒水进去
5. 搅拌

这就是把一句话**拆成一步步能执行的小动作**。

编程也一样：

- 你写的 C 代码是"做杯咖啡"
- 汇编是"拿杯子、烧水、放粉……"
- CPU 只会执行这些小动作

---

## 一个真实例子

你写了这句 C 代码：

```c
int sum = a + b;
```

你觉得这是"把 a 和 b 加起来"。但 CPU 要做三步：

1. 把 `a` 的值拿到手
2. 把 `b` 的值拿到手
3. 把它俩加起来，结果存到 `sum`

汇编就是把这三步写出来。可能长这样：

```asm
add  a0, a1, a2
```

意思是：把 `a1` 和 `a2` 加起来，结果放到 `a0`。

**这里的 `a0`、`a1`、`a2` 叫"寄存器"（Register），你可以理解成 CPU 手里的三个小盒子，专门用来临时放数字。**

---

## 寄存器（Register）是什么

想象 CPU 是个收银员，手边有 32 个小格子（寄存器），每个格子能放一个数字。

- 格子编号叫 `x0`、`x1`、`x2`……`x31`
- 有些格子有外号，比如 `a0`、`a1` 是"参数格"，通常用来传输入和输出
- CPU 做计算时，只能从这些格子里拿数字，算完再放回去

**重点：CPU 不能直接从内存（Memory）拿数字来加，必须先把数字搬到寄存器里。**

---

## 汇编指令（Instruction）怎么看

每条汇编指令就是一个小动作。格式通常是：

```
动作  目标格子, 来源格子1, 来源格子2
```

例子：

```asm
add  a0, a1, a2    # 把 a1 和 a2 加起来，结果放到 a0
sub  a0, a1, a2    # 把 a1 减去 a2，结果放到 a0
```

再看一个完整流程：

```asm
li   a1, 5        # 把数字 5 放到 a1（li = load immediate，直接装载数字）
li   a2, 3        # 把数字 3 放到 a2
add  a0, a1, a2   # a1 + a2，结果放到 a0（现在 a0 = 8）
```

**读汇编只需要跟着数字走：看数字从哪个格子来，算完放到哪个格子去。**

---

## 你现在能做什么

看到这样的汇编：

```asm
li   a1, 10
li   a2, 20
add  a0, a1, a2
```

你应该能回答：

- 输入是什么？（10 和 20）
- 结果是什么？（30）
- 结果放在哪里？（a0）

就这么简单。
