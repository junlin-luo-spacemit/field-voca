# 02 RV32I 基础指令

**前置阅读**：[[01-计算机与RISC-V入门|← 01 计算机与RISC-V入门]]

## 你要学什么

上一章你知道了 CPU、寄存器、内存这些基本概念。现在要学 CPU 能做哪些具体动作。

**RV32I 是 RISC-V 最基础的指令集（Instruction Set），包含 CPU 必须会的 47 个基本动作。**

### 为什么要学这个？

知道了寄存器和内存，但还不知道怎么让 CPU 干活。就像知道厨房有锅碗瓢盆，但不知道怎么炒菜。

**这一章解决的问题：**
- 怎么把两个数加起来？（算术指令）
- 怎么从内存读数据？（加载指令）
- 怎么根据条件跳转？（分支指令）

学完后，你就能看懂汇编代码中的每条指令在做什么。下一章会把这些指令组合成完整程序。

---

## 从生活例子开始

想象你有个工具箱，里面有三类工具：

### 1. 计算工具（算术指令）

**类比：计算器**

```asm
add  x7, x5, x6    # 把 x5 和 x6 加起来，结果放到 x7
sub  x7, x5, x6    # 把 x5 减去 x6，结果放到 x7
```

- `add` = 加法（Addition）
- `sub` = 减法（Subtraction）

这就像用计算器：按 `5 + 3`，得到 `8`。

### 2. 搬运工具（内存访问指令）

**类比：取放工具**

CPU 手边的格子（寄存器）只有 32 个，数据多了放不下，要存到大仓库（内存）。

```asm
lw   x5, 0(x10)    # Load：从内存地址 x10+0 读一个数到 x5
sw   x5, 0(x10)    # Store：把 x5 的值写到内存地址 x10+0
```

- `lw` = load word（加载一个字）
- `sw` = store word（存储一个字）
- "字"（word）在 RV32I 里是 4 字节（32 位）

**为什么要这样？**

记得上一章说的：CPU 不能直接用内存里的数字算，必须先搬到寄存器。

```asm
# 错误：CPU 不能这样做
add  内存[100], 内存[200], 内存[300]

# 正确：先搬到寄存器，算完再搬回去
lw   x5, 0(x10)     # 从内存读到 x5
lw   x6, 4(x10)     # 从内存读到 x6
add  x7, x5, x6     # 在寄存器里算
sw   x7, 8(x10)     # 结果写回内存
```

### 3. 路线选择工具（跳转指令）

**类比：导航路标**

程序不总是从上往下执行，有时要跳到别的地方，或者根据条件选择不同路线。

```asm
beq  x5, x6, target    # Branch if Equal：如果 x5 == x6，跳到 target
bne  x5, x6, target    # Branch if Not Equal：如果 x5 != x6，跳到 target
jal  ra, function      # Jump and Link：跳到 function，同时记住回来的地址
```

- `beq` = branch if equal（相等时跳转）
- `bne` = branch if not equal（不相等时跳转）
- `jal` = jump and link（跳转并记录返回地址）

## 指令的格式（Format）

每条指令在内存里是 32 位的二进制数字。为了让 CPU 快速理解，指令分成几个固定格式：

**类比：不同工具的包装盒**

- **R 格式**：两个输入格子，一个输出格子（如 `add x7, x5, x6`）
- **I 格式**：一个输入格子 + 一个立即数（如 `addi x5, x5, 10`）
- **S 格式**：存储指令（如 `sw x5, 0(x10)`）
- **B 格式**：条件跳转（如 `beq x5, x6, target`）
- **U 格式**：大立即数（如 `lui x5, 0x12345`）
- **J 格式**：无条件跳转（如 `jal ra, function`）

**现在不用背这些格式**，只需要知道：不同类型的指令有不同的"包装盒"，方便 CPU 快速找到需要的信息。

## 一个完整例子

假设你要计算：`result = (a + b) * 2`，数据在内存里。

```asm
# 假设 x10 指向内存里存 a 的地方
lw   x5, 0(x10)      # 读 a 到 x5
lw   x6, 4(x10)      # 读 b 到 x6（下一个位置，+4字节）

add  x7, x5, x6      # x7 = a + b

addi x8, x7, x7      # x8 = x7 + x7 = (a+b)*2
# 或者用左移：slli x8, x7, 1

sw   x8, 8(x10)      # 把结果写回内存
```

**跟着数字走：**
1. `a` 和 `b` 从内存搬到 `x5`、`x6`
2. 在寄存器里算出 `x7 = a + b`
3. 再算 `x8 = x7 * 2`
4. 结果搬回内存

## 常用指令速查

### 算术指令（Arithmetic）

| 指令 | 意思 | 例子 | 说明 |
|------|------|------|------|
| `add` | 加法 | `add x7, x5, x6` | x7 = x5 + x6 |
| `sub` | 减法 | `sub x7, x5, x6` | x7 = x5 - x6 |
| `addi` | 加立即数 | `addi x5, x5, 10` | x5 = x5 + 10 |
| `slli` | 左移 | `slli x5, x5, 1` | x5 = x5 << 1（相当于 ×2）|
| `srli` | 右移 | `srli x5, x5, 1` | x5 = x5 >> 1（相当于 ÷2）|

### 内存访问（Memory Access）

| 指令 | 意思 | 例子 | 说明 |
|------|------|------|------|
| `lw` | 加载字 | `lw x5, 0(x10)` | 从内存地址 x10+0 读 4 字节到 x5 |
| `sw` | 存储字 | `sw x5, 0(x10)` | 把 x5 的 4 字节写到内存地址 x10+0 |
| `lb` | 加载字节 | `lb x5, 0(x10)` | 读 1 字节（带符号扩展）|
| `sb` | 存储字节 | `sb x5, 0(x10)` | 写 1 字节 |

### 跳转指令（Control Flow）

| 指令 | 意思 | 例子 | 说明 |
|------|------|------|------|
| `beq` | 相等则跳 | `beq x5, x6, label` | 如果 x5 == x6，跳到 label |
| `bne` | 不等则跳 | `bne x5, x6, label` | 如果 x5 != x6，跳到 label |
| `blt` | 小于则跳 | `blt x5, x6, label` | 如果 x5 < x6，跳到 label |
| `jal` | 跳转并链接 | `jal ra, func` | 跳到 func，返回地址存到 ra |
| `jalr` | 寄存器跳转 | `jalr ra, 0(x5)` | 跳到 x5+0 的地址 |

## 为什么要分这么多指令

你可能会问：为什么不直接一条指令做完所有事？

**答案：简单指令 = 快速执行**

- 每条指令只做一件小事，CPU 可以在一个时钟周期内完成
- 复杂的操作（如 `(a+b)*2`）由多条简单指令组合完成
- 这就是 RISC（Reduced Instruction Set Computer，精简指令集）的设计哲学

**对比：**
- **RISC-V**：47 条基础指令，每条很简单，组合使用
- **x86（CISC）**：上千条指令，有些指令很复杂，但向后兼容包袱重

## 你现在能做什么

看到这段代码：

```asm
lw   x5, 0(x10)
addi x5, x5, 1
sw   x5, 0(x10)
```

你应该能回答：

- 第一行做什么？（从内存读数到 x5）
- 第二行做什么？（x5 加 1）
- 第三行做什么？（把 x5 写回内存）
- 整体做什么？（把内存里的数加 1）
