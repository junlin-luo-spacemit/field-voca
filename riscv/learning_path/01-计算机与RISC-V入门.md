# 01 计算机与 RISC-V 入门

**前置阅读**：[[00-学习导航|← 00 学习导航]] 

## 你要学什么

这是 RISC-V 学习的第一步，要搞清楚三个基本概念：**CPU、寄存器、内存。**

**核心思想：数据从内存搬到寄存器，CPU 在寄存器里算，结果再搬回内存。**

### 为什么要学这个？

在学习导航中，你已经知道 RISC-V 是什么。但要真正看懂汇编代码，必须先理解计算机的基本工作方式。就像学开车前要知道油门、刹车、方向盘的作用。

**这一章解决的问题：**
- 为什么 CPU 不能直接用内存里的数据算？
- 寄存器和内存有什么区别？
- 一条指令执行时，数据怎么流动？

理解了这些，下一章学指令时才知道每条指令在操作什么。

## 从生活例子开始

想象你在办公桌前工作：

### 场景：计算两个数的和

- **你** = CPU（中央处理器）：负责干活
- **桌上的文件夹** = 寄存器（Register）：手边能放的东西有限（32个）
- **档案柜** = 内存（Memory）：能放很多东西，但离你远一些

**任务**：把档案柜里的两个数字相加。

**你会怎么做？**

1. 从档案柜拿出第一个数字，放到桌上左边的文件夹
2. 从档案柜拿出第二个数字，放到桌上右边的文件夹
3. 看着桌上两个文件夹的数字，心算出结果
4. 把结果写到桌上第三个文件夹
5. 把结果文件夹放回档案柜

**为什么不能直接对着档案柜算？**
- 档案柜离你太远，每次要走过去
- 计算时需要同时看两个数字，档案柜打开太慢

**寄存器就是你桌上的文件夹：数量少，但拿取飞快。**

## 三个核心概念

### 1. CPU（Central Processing Unit，中央处理器）

**CPU 是真正干活的人。**

它做三件事：
1. **读指令**：看下一步要做什么（如"把两个数加起来"）
2. **取数据**：从寄存器拿数字
3. **执行计算**：做加减乘除等运算

**类比**：办公桌前的你，按照任务清单一步步操作。

### 2. 寄存器（Register）

**寄存器是 CPU 手边的小格子，用来临时放数据。**

RISC-V 有 32 个通用寄存器：
- 编号：`x0`、`x1`、`x2`……`x31`
- 每个格子能放一个数字（32位系统放32位，64位系统放64位）
- `x0` 特殊：永远是 0，不能改

**类比**：桌上的32个文件夹，编号 0-31。

**为什么只有32个？**
- 寄存器是 CPU 内部的，速度极快但成本高
- 32个对大多数程序够用了
- 更多的数据放在内存里

### 3. 内存（Memory）

**内存是大仓库，能放很多数据，但比寄存器慢。**

- 容量大：几GB到几十GB
- 速度慢：比寄存器慢100倍
- 每个位置有地址：`0x0000`、`0x0001`、`0x0002`……

**类比**：办公室的档案柜，能放很多文件，但拿取比桌上慢。

**程序和数据都在内存里。**

## CPU 怎么执行一条指令

假设要执行这条 RISC-V 指令：

```asm
add  x7, x5, x6    # x7 = x5 + x6
```

**步骤：**

1. **取指令（Fetch）**：CPU 从内存读这条指令
2. **解码（Decode）**：CPU 理解指令意思："把 x5 和 x6 加起来，放到 x7"
3. **读寄存器**：CPU 读 x5 和 x6 的值（如 x5=10, x6=20）
4. **执行（Execute）**：CPU 内部的 ALU（算术逻辑单元）算出 10+20=30
5. **写回（Write Back）**：把 30 写到 x7

**整个过程不碰内存，全在 CPU 和寄存器之间完成，所以很快。**

## 为什么要区分寄存器和内存

### 如果只有内存，没有寄存器会怎样？

```asm
# 假设 CPU 能直接用内存算（实际不行）
add  内存[100], 内存[200], 内存[300]
```

**问题：**
1. **太慢**：每次都要去内存拿数据，慢100倍
2. **复杂**：CPU 设计会非常复杂

### 有了寄存器：

```asm
lw   x5, 0(x10)     # 从内存读到 x5（慢）
lw   x6, 4(x10)     # 从内存读到 x6（慢）
add  x7, x5, x6     # 在寄存器里算（快！）
sw   x7, 8(x10)     # 写回内存（慢）
```

**好处：**
- 计算部分（`add`）很快，因为数据在寄存器
- 只在需要时才访问内存（`lw`/`sw`）

**类比**：你不会每次算数都跑去档案柜，而是先把文件拿到桌上，算完再放回去。

## 一个完整例子

假设内存里有两个数：`a=5`（地址0x1000），`b=3`（地址0x1004），要算 `c = a + b`。

```asm
# x10 = 0x1000（基地址）
lw   x5, 0(x10)      # 从 0x1000 读 a 到 x5
lw   x6, 4(x10)      # 从 0x1004 读 b 到 x6
add  x7, x5, x6      # x7 = x5 + x6 = 5 + 3 = 8
sw   x7, 8(x10)      # 把 x7 写到 0x1008
```

**数据流动：**
```
内存(0x1000: a=5) → lw → x5 (5)
内存(0x1004: b=3) → lw → x6 (3)
                         ↓
                   x5 + x6 = 8
                         ↓
                       x7 (8)
                         ↓
                   sw → 内存(0x1008: c=8)
```

**关键点：加法在寄存器里完成，不碰内存。**

## PC：程序计数器

还有一个特殊寄存器：**PC（Program Counter，程序计数器）**。

**PC 记录"下一条指令在哪里"。**

```asm
地址 0x100:  lw   x5, 0(x10)    # PC = 0x100，执行这条
地址 0x104:  add  x7, x5, x6    # PC = 0x104，执行完上一条后到这
地址 0x108:  sw   x7, 8(x10)    # PC = 0x108
```

**执行流程：**
1. CPU 读 PC 指向的指令（0x100）
2. 执行这条指令
3. PC 自动 +4（下一条指令）
4. 重复

**类比**：书签，记录你读到第几页。

**跳转指令可以改变 PC：**
```asm
beq  x5, x6, target    # 如果 x5 == x6，PC 跳到 target 地址
```

## RISC-V 的设计哲学

**RISC = Reduced Instruction Set Computer（精简指令集计算机）**

### 核心思想：简单指令 = 快速执行

- 每条指令只做一件小事
- 复杂操作由多条简单指令组合完成
- CPU 设计简单，容易优化速度

**例子：**
- **RISC-V**：没有"内存直接相加"的指令，必须先 `lw` 再 `add`
- **CISC（x86）**：有复杂指令，一条指令能做很多事，但速度优化难

**类比：**
- RISC-V 像乐高积木：每块很简单，但组合灵活
- x86 像预制模型：功能多，但不够灵活

## 你现在能做什么

看到这段代码：

```asm
lw   x5, 0(x10)
add  x5, x5, x5
sw   x5, 0(x10)
```

你应该能回答：

- 第一行做什么？（从内存读数到 x5）
- 第二行做什么？（x5 = x5 + x5，数字翻倍）
- 第三行做什么？（把 x5 写回内存）
- 为什么 `add` 不直接用内存？（CPU 只能在寄存器里算）
